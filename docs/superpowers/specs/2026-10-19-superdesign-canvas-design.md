# Канвас в стиле Superdesign — фаза 1

## Зачем

Сейчас канвас Design Hub — это доска с фреймами и деревом итераций. Claude видит
только дизайн: бриф, DESIGN.md, HTML страниц. Пользователь хочет канвас
как в Superdesign. Там страницы связаны в пользовательский путь, у проекта
есть закреплённый контекст о самом приложении и его работе, а интерфейс
устроен по-другому: плавающие тёмные панели, миникарта, левый тулбар и чат
агента справа. Sipuni в скриншотах — только пример. Нужна функциональность,
а не конкретный проект.

Успех: открыв канвас, пользователь видит flow приложения стрелками между
страницами и держит рядом заметки о том, как приложение работает. Claude
получает эти связи и закреплённые заметки с каждым запросом, поэтому новые
страницы и правки согласуются с логикой продукта, а не только со стилем.

## Цели (фаза 1)

1. **Связи страниц (navigation edges).** Синяя стрелка `#3B82F6` с подписью
   (например «Source», «Login → Dashboard»). Её создают:
   - перетаскиванием с ручки на краю фрейма на другой фрейм;
   - кнопкой «Link» при выделении двух фреймов;
   - Claude через MCP.
   Подпись редактируется двойным кликом, связь удаляется Delete. Связи
   родитель→итерация (lineage) остаются, но рисуются тонким серым пунктиром.
   Фильтр «Show connections»: все / только навигация / скрыть.
2. **Заметки и Pinned Context.** Новый тип узла — заметка (стикер, markdown,
   редактируется на месте, цвет из 4–5 вариантов). У заметки есть флаг
   «pinned». Все закреплённые заметки уходят Claude с каждым запросом:
   в `canvas_wait_feedback`, в `project_get` и в промпт фонового раннера.
   Это канал для контекста «как работает приложение»: роли, бизнес-правила,
   сущности, состояния, интеграции. При создании проекта автоматически
   появляется закреплённая заметка «Design Context». В ней бриф и ссылка
   на DESIGN.md, если он есть. Это обычная заметка, её можно править
   и удалять.
3. **Раскладка UI как у Superdesign** (тёмная тема уже сделана):
   - слева сверху: имя проекта, статус, кнопка Layers (панель списка узлов
     с поиском, клик → fly-to);
   - по центру сверху: Fit, меню зума 10–300 % с пресетами, переключатель
     View / Edit (View — только просмотр и навигация, Edit — правка);
   - справа сверху: миникарта (кликом/перетаскиванием двигает вид), индикатор
     «Claude listening», кнопка Agent;
   - левый вертикальный тулбар:
     - Select (V) / Hand (H);
     - Note (N);
     - Auto layout;
     - Duplicate;
     - счётчик Pinned Context (клик → список закреплённых заметок);
   - правая выезжающая панель **Agent**: сюда переезжают композер и Activity
     (запросы, ответы, лог раннера, критики, design system); внизу поле ввода;
   - текущий нижний композер убирается, его функции переходят в Agent-панель
     и в тулбар узла.
4. **Тулбар выбранного фрейма** (над фреймом):
   - **Update ▾**: свободный текст плюс пресеты Color / Layout / Style /
     Typography. Каждый пресет — заготовка текста запроса, которую можно
     дописать.
   - **Create New ▾**:
     - Variations N — как сейчас;
     - Next page in flow: Claude делает новую страницу, канвас ставит её
       справа и сразу связывает навигационной связью с подписью из запроса.
   - **Select element** — как сейчас;
   - **Interact**;
   - вьюпорт mobile / tablet / desktop;
   - **Pin**: «выбранный дизайн», сейчас это «Choose»;
   - **Export ▾**: Copy prompt / Copy HTML / Open;
   - **Delete**.
5. **Работа с канвасом.**
   - мультивыделение: Shift+клик и рамка по пустому месту;
   - перетаскивание группы;
   - привязка к сетке 24 px (та же, что точки фона);
   - Undo/Redo (Ctrl+Z / Ctrl+Shift+Z) для перемещений, создания
     и удаления заметок и связей, правки подписей и удаления фреймов;
   - **Auto layout**: раскладывает фреймы слева направо по навигационным
     связям (порядок flow), итерации — колонкой под родителем, заметки
     не трогает.
6. **MCP для Claude.**
   - `project_get` возвращает `edges` (from, to, label) и `context`
     (закреплённые заметки целиком), а в дереве у узлов — их исходящие
     навигационные связи;
   - новый инструмент `canvas_link(project, from, to, label)` — создать
     или удалить связь;
   - новый инструмент `canvas_note(project, text, pinned?, near?, id?)` —
     создать, изменить или удалить заметку;
   - `design_write` получает необязательные `link_from` и `link_label`:
     новая страница сразу связывается с исходной (для запроса «Next page
     in flow»);
   - `hub_workflow` / инструкции раннера: читать `context` перед работой;
     при генерации многостраничного flow создавать связи; если пользователь
     рассказал о логике продукта, предлагать сохранить это закреплённой
     заметкой.

## Не цели (фаза 1)

- Visual Edit (правка стилей кликом), Annotate, вставка картинок
  drag-and-drop — это фаза 2.
- История версий с откатом: сейчас `writeNode` перезаписывает файл,
  а для истории нужны файлы ревизий. Это отдельная задача после фазы 1.
- Кредиты, выбор модели, команды и шаринг, publish и домены, Figma, Mobbin,
  генерация картинок и видео, Chrome-расширение — исключено совсем.
- React / React Flow: канвас остаётся на vanilla JS, без сборки.

## Анти-цели

- Тормоза: при 30+ фреймах панорама и зум должны оставаться плавными.
  Миникарта рисуется дешёво (canvas-прямоугольники), а не клонами iframe.
- Потеря данных: связи и заметки хранятся в `project.json` рядом с узлами
  и не теряются при удалении фрейма. Связи удалённого фрейма удаляются,
  но это действие отменяется через Undo.
- Заметки, которые Claude не видит: если пользователь закрепил контекст,
  он обязан доходить до Claude во всех трёх путях (сессия, `project_get`,
  фоновый раннер).

## Ограничения

- Стек: Node ESM без сборки. Статика — `src/preview/static/{canvas.html,
  canvas.css,canvas.js,inject.js}`, сервер — `src/preview/http.js`,
  модель — `src/workspace.js`, инструменты — `src/tools.js`, раннер —
  `src/runner.js`.
- Фреймы — iframe в sandbox без allow-same-origin. Всё взаимодействие
  с содержимым идёт через postMessage из `inject.js`.
- Обновление канваса идёт через SSE `/events`. Новые сущности (edges, notes)
  синхронизируются тем же механизмом, что и узлы.
- Тёмная тема и токены уже лежат в `canvas.css` (`--signal: #3b82f6` —
  акцент и цвет навигационных связей).

## Модель данных (решено)

В `project.json`:

- `edges: [{ id, from, to, label, kind: 'nav' }]` — `id` из общего `seq`,
  например `e1`. Lineage-связи не хранятся, они выводятся из `parent`.
- Заметки — отдельный массив
  `notes: [{ id, text, pinned, color, pos, size, createdAt, updatedAt }]`
  с id `t1…`, а не узлы. У узлов есть файл, вьюпорт и ревизии, у заметок
  этого нет, и смешивать их неудобно.
- Старые проекты без `edges` / `notes` грузятся как с пустыми массивами.

HTTP API (по образцу существующего `/nodes/:id`):

- `POST/PATCH/DELETE /api/p/<slug>/edges[/:id]`;
- `POST/PATCH/DELETE /api/p/<slug>/notes[/:id]`.

## Решения автора дока (можно оспорить)

- **Undo удаления фрейма** возвращает тот же узел: тот же id, файл, позицию,
  связи, `selected` и `parent` у детей. Удалённый узел целиком (запись,
  id детей, его связи) кладётся в `project.json` → `trash[]`, HTML
  по-прежнему уходит в `.trash/`. Восстановление — через
  `POST /api/p/<slug>/nodes/:id/restore`. Claude корзину не видит.
- **Undo** охватывает только действия пользователя в этой вкладке.
  Изменения, пришедшие по SSE (от Claude или из другой вкладки), в стек
  не попадают. Если цель шага уже исчезла, шаг пропускается с тостом.
- **«Next page in flow»** — это новый корневой узел, не итерация.
  - Он связан навигационной связью с исходной страницей.
  - Тип запроса — `next-page`, текст подписи берётся из необязательного
    поля запроса. Если поле пустое, подпись выбирает Claude
    (`link_label`).
  - Позицию справа от исходной страницы ставит сервер в `design_write`
    при `link_from`, чтобы это работало и в фоновом раннере.
- **View / Edit**:
  - по умолчанию Edit, режим запоминается в localStorage;
  - View запрещает перемещение, создание и удаление узлов, заметок
    и связей, правку подписей и текста заметок;
  - выделение, Interact, Open/Export и запросы к Claude из Agent-панели
    в View остаются.
- **Проверка** — новый скрипт `scripts/canvas-check.mjs` в репо (старый
  zoom-check лежал вне репо, его проверки переносятся сюда).
  - Playwright: `playwright-core` с системным Chrome, как в
    `design_screenshot`.
  - MCP-часть вызывается через HTTP-эндпоинт `/mcp` превью-сервера,
    без stdio.

## Оставлено исполнителю

- Точная вёрстка панелей, иконки (inline SVG, как сейчас), анимации.
- Алгоритм auto layout в пределах описанного поведения.
- Как именно хранить стек Undo (в памяти вкладки, не персистентно — это
  нормально).
- Рисование стрелок (SVG-путь в `#links`, кривая Безье между ближайшими
  сторонами фреймов) и размещение подписи.
- Разбиение `canvas.js` на несколько файлов, если он станет слишком большим.
  Без бандлера: обычные `<script>` или ES-модули.

## Проверка

- Расширить headless-скрипт (Playwright, как `zoom-check`):
  - создать проект;
  - создать связь и заметку через API, проверить, что они отрисованы;
  - проверить, что закреплённая заметка попадает в ответ `project_get`
    и в запрос `canvas_wait_feedback`;
  - проверить Undo перемещения.
- Скриншот для визуальной сверки с референсом Superdesign.
